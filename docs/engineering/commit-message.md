## What it does

`commit-message` 根据整个暂存区的改动，生成符合 Conventional Commits 规范的提交信息。它只负责生成文本。

相关改动归入同一提交，明显独立的改动则建议拆分，为每个提交分别提供完整提交信息和对应范围。语言遵循项目的提交信息规范或已有提交惯例。

## When to reach for it

仅由用户手动输入 `/commit-message` 调用。

- 完成 `/implement` 后，希望为已暂存的改动生成提交信息。
- 独立完成并暂存改动后，希望准确概括本次提交。
- 暂存区混有不同用途的改动，希望获得拆分建议及各自的提交信息。

## Prerequisites

在 Git 仓库中使用，并先暂存希望纳入提交信息的改动。分析范围是整个暂存区。

## Common questions

**提交信息使用什么语言？**

| 项目情况 | 语言选择 |
| --- | --- |
| 有明确的提交信息语言规范 | 遵循规范，即使近期提交使用了其他语言。 |
| 没有明确规范，但近期提交有主要语言 | 沿用该语言。 |
| 没有提交历史，或多种语言混用且无法判断主要语言 | 先询问你，得到答复后再生成提交信息。 |

例如，你用中文交流，而项目一直使用英文提交，生成的主题和正文仍使用英文。

**暂存区为空时会怎样？**

它会提示没有暂存改动并结束。

**建议拆分时，会替我调整暂存区吗？**

不会。它会说明拆分理由、每个建议的提交对应的文件或具体改动，并分别给出完整提交信息。重新分组暂存属于后续操作。

**拿到提交信息后，必须自己执行提交吗？**

不必。你可以自行提交，也可以确认内容后另行要求 AI 执行。执行提交不属于这个技能的职责。

## It's working if

- 提交信息中的改动描述与暂存内容一致，没有把未暂存改动写进去。
- 主题和正文的语言符合项目规范或已有提交惯例；无法判断时，会先询问你。
- 所有暂存改动都有对应的提交信息，明显独立的改动得到清晰的拆分建议。
- 每条完整提交信息都在独立、可复制的代码块中。
- 调用前后，工作区和暂存区保持不变，也没有新增提交。

## Where it fits
