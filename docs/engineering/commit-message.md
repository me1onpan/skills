## What it does

`commit-message` 根据整个暂存区的改动，生成符合 Conventional Commits 规范的提交消息。它只生成提交消息。

提交意图决定消息的边界：相关改动用一条消息描述，明显独立的改动则建议拆分，并分别给出消息和对应范围。

## When to reach for it

仅由用户手动输入 `/commit-message` 调用。

- 完成 `/implement` 后，希望为已暂存的改动生成提交消息。
- 独立完成并暂存改动后，希望准确概括本次提交。
- 暂存区混有不同用途的改动，希望获得拆分建议及各自的提交消息。

## Prerequisites

在 Git 仓库中使用，并先暂存希望纳入提交消息的改动。分析范围是整个暂存区。

## Common questions

**暂存区为空时会怎样？**

它会提示没有暂存改动并结束。

**建议拆分时，会替我调整暂存区吗？**

不会。它会说明拆分理由、每个建议的提交对应的文件或具体改动，并分别给出完整消息。重新分组暂存属于后续操作。

**拿到消息后，必须自己执行提交吗？**

不必。你可以自行提交，也可以确认消息后另行要求 AI 执行。执行提交不属于这个技能的职责。

## It's working if

- 消息中的改动描述与暂存内容一致，没有把未暂存改动写进去。
- 所有暂存改动都有对应的提交消息，明显独立的改动得到清晰的拆分建议。
- 每条完整消息都在独立、可复制的代码块中。
- 调用前后，工作区和暂存区保持不变，也没有新增提交。
